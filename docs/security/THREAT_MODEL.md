## Actors
Malicious node, malicious/compromised `quorum_service`, malicious client, network attacker, insider, malicious DKG dealer. 

## Trust boundaries
1. client <-> `quorum_service` (HTTP; the service terminates TLS itself and refuses plaintext off loopback, `quorum_service/src/tls_serve.rs`, `main.rs:1213-1217`; adversarial group K, EXECUTED). Caller identity is a bearer API key compared by SHA-256 digest in constant time (`main.rs:195-203`). **`GET /audit-log` and `GET /invoices/:id/merkle-proof` take no credentials at all, by design (the handler comments call them public, mirroring the earlier canister's methods) (`main.rs:984`, `:1022`), and `/audit-log` is served from the first configured node's replica only (`main.rs:988-992`) (F-26).**
2. `quorum_service` <-> nodes (pinned-certificate mutual TLS + per-node HMAC derive auth)
3. nodes <-> nodes (mutual TLS: DKG pushes and audit vote/replicate/commit-ack). `quorum_notary` is reached by a client that chooses to submit a root hash (mutual TLS); no node or the service does so on its own (F-24)
4. service <-> Postgres: **plain TCP, no TLS.** The service builds its pool and the `migrate` subcommand with `tokio_postgres::NoTls` (`quorum_service/src/main.rs:1180,1237`), so a `sslmode` in `db_url` cannot be honoured (READ; F-27). Protection of this hop rests on network placement, which this repository does not configure
5. system <-> any external authority: **NONE exists in code** — the `VerificationAttestation` object is not built (READ: the only occurrences in `src/` are comments, e.g. `quorum_vetseal/src/nizk.rs:64`)

## Attack paths

| ID | Path | Status | Mitigations / Evidence |
|---|---|---|---|
| T-1 | Node-level authorization bypass | Mitigated | HMAC derive auth bound to identity + expiry + nonce + transport key (READ: `quorum_core/src/lib.rs:152-176`, verified constant-time at `:179-199`, enforced at `quorum_node/src/main.rs:751-767`); evidence via adversarial test group C (EXECUTED). Scope: the node checks the MAC, not who the caller is; per-invoice policy is the service's job |
| T-2 | Replay of a derive request | Mitigated | Requests whose expiry is more than `MAX_DERIVE_AUTH_WINDOW_MS = 30_000` ms ahead are refused (`quorum_core/src/lib.rs:105`, `quorum_node/src/main.rs:737`); a used nonce is remembered until its expiry and a second use is refused (`:784-797`); evidence via adversarial test group D (EXECUTED) |
| T-3 | Replay after node restart | Mitigated with caveat | A restart guard refuses any request a previous process could have accepted, given a non-stepping wall clock (READ: `quorum_core/src/lib.rs:129-150`, `quorum_node/src/main.rs:769-782`); evidence via test group L (EXECUTED). **Caveat:** the guard is time-based, so it does not defend against a wall clock that steps backwards, and the in-memory nonce store is lost on restart. |
| T-4 | Compromised service (holder of the master `service_auth_key`) authorizes any invoice on every node | **Open / Accepted Risk** | A single leaked NODE key no longer does this (per-node HKDF keys, group S EXECUTED), but the master at the service still does. | T-5 | Malicious DKG dealer, wrong degree | Mitigated | Commitments of the wrong degree are rejected at receipt (`receive_commitment` returns `Result`; commitment length must equal `t+1` or the dealer id is out of range, `quorum_core/src/bls.rs:276-290`; READ) |
| T-5b | Malicious DKG dealer, valid degree but dishonest share | **Open** | Detected as a `Complaint` and the complaining node never finalizes; there is no protocol to exclude a confirmed-bad dealer and continue. Availability impact only. **Also still open (`SECURITY_REVIEW.md` R-3, READ): the `from` field of `DkgCommitment`/`DkgShare` is not bound to the connection's certificate (`quorum_node/src/main.rs:676-682`) and `receive_commitment` overwrites the stored commitment for that id (`bls.rs:290`), so any pinned-certificate holder can impersonate a dealer during the DKG window. Share persistence (Gap 1) limits the DKG window to the init ceremony; it does not remove the problem.** |
| T-6 | Concurrent audit-log writers lose a write, or split a quorum | **Open** | Partial fixes: only signatures that verify over the entry hash are stored (R-1, READ `quorum_node/src/main.rs:929-941`); `quorum_service` serializes its own proposals behind one lock (F-13, `main.rs:262-312`), writes state changes and an `audit_outbox` row atomically, and a node acknowledges only after an fsynced commit (F-19; groups Y, Z, R EXECUTED). **The vote-TTL split-quorum hazard (R-2) is still open at the protocol level** (`PENDING_AUDIT_VOTE_TTL` = 5 s, `quorum_node/src/main.rs:261`): a proposer slower than the TTL can obtain overlapping votes and produce two conflicting "committed" entries, and two service replicas are two proposers. | T-7 | Unsealed share or plaintext visible on node->service bytes | Mitigated | READ: `quorum_node/src/main.rs:800-860` seals each partial to the caller's transport key (with a NIZK) before it leaves the node, and runs a release-build self-check first (`checked_partial`, F-22, EXECUTED 2/2) |
| T-8 | mTLS misconfiguration / cert handling | Mitigated | Certificate pinning is exact-DER-equality (READ: `quorum_node/src/tls.rs:29-58`, no CA or hostname check); adversarial test groups F and K (EXECUTED) cover certificate constraints and TLS enforcement. ## The load-bearing architectural gap

T-4 above is the sharpest version of a gap that runs through the whole design: no `VerificationAttestation` from any external authority is checked anywhere in the system today. Authorization rests entirely on a master HMAC secret held by `quorum_service`, from which each node's verification key is derived (`quorum_core/src/lib.rs:213-218`). Until an externally-signed attestation object exists and is independently verified by each node, any claim that access is conditioned on a regulator's verified result is aspirational rather than implemented. This is tracked as §6a of `CipherSettle_Audit_Remediation_Roadmap.md`.
