## F-24 .. F-29 (session 25, found by the line-by-line THREAT_MODEL read; all READ at commit 87f3a17 unless stated)
- **F-24 (Medium, detection gap):** audit reconciliation (`AuditLog::majority_reference` / `diverges_from`) and external notarization (`quorum_client::notarize`, `send_notary_request`) are called only by `quorum_orchestrator` and the adversarial suite. No long-running component (`quorum_service`, `quorum_node`, `quorum_notary`) runs either, so a tampered node log is detected only when an operator or test runs them. The docs described notarization/reconciliation as part of the running system. READ (grep over `src/`). Fix needs a scheduled reconciler/notarizer: new component, product decision.
- **F-25 (Low-Medium):** `majority_reference` counts votes only among nodes that HAVE an entry at a sequence (`winning_count * 2 <= votes.len()`, `quorum_audit/src/lib.rs`), so one node reporting a longer log extends the reference with its own entry (1 of 1 is a strict majority). A single malicious node can therefore put an invented tail entry into the reference. READ, and pinned by a characterisation unit test (`lone_reporter_extends_the_reference_f25`) that documents the CURRENT behaviour; flip it when fixed. Fix = require a majority of ALL configured nodes (a protocol-semantics change, review needed).
- **F-26 (Medium, information disclosure):** `GET /audit-log` and `GET /invoices/:id/merkle-proof` take no credentials (the handlers never call `authenticate`), and `/audit-log` is served from the FIRST configured node's replica only. Both are PUBLIC BY DELIBERATE DESIGN (handler comments: "public, metadata only", mirroring the earlier canister's public methods), so this is a disclosure/policy question, not an accident: entries expose invoice ids, actors and actions to anyone who can reach the service. READ (`quorum_service/src/main.rs` `get_audit_log`, route table). Not fixed (needs an owner decision on who may read the log).
- **F-27 (Medium, deployment):** the service talks to Postgres over plain TCP (`tokio_postgres::NoTls` in the pool and the `migrate` subcommand), so `sslmode` in `db_url` cannot be honoured. Protection depends on network placement, which the repo does not configure. READ.
- **F-28 (Low-Medium):** `insecure_skip_share_proofs` (test-only) disables NIZK verification of sealed shares; the service only logs a warning and starts. Nothing refuses it outside tests. READ.
- **F-29 (Info):** the doc comment on `NodeConfig::service_auth_key_b64` still describes a key shared by every node; the code path uses the per-node derived key (Gap 3 step 1). READ.
